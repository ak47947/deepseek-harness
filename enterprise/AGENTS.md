# AGENTS.md — Enterprise integration

These rules supplement the [repository instructions](../AGENTS.md). The [package map](README.md) names each enterprise owner; [enterprise architecture](../docs/ent-agent/enterprise_agent_harness_proposal.md) owns deployment and isolation requirements.

- Keep enterprise implementation, configuration, deployment files, artwork, packaging helpers, fixtures, and tests under `enterprise/`. Use `backend/` for the server, `protocol/` for shared validation, `account/` for account UI and identity, `bundle/` for profile composition, and `desktop/` for native adaptation. Shared protocol imports must not load the server, database, or Electron.
- Prefer Cordis plugins and bundles for enterprise Host and Client behavior. Reuse the standard DSH profile, model adapters, settings, credentials, slots, and tools. Keep account data in its profile and credentials in their owning store. Do not duplicate the Desktop main program, renderer application, or agent loop.
- Keep shared-tree changes limited to necessary generic interfaces and their consumers. Native product operations and preload integration must document inputs, side effects, failure handling, and cleanup. Keep enterprise URLs, account policy, and branding implementation in their enterprise owner. Exercise the enterprise and ordinary product paths when changing an interface.
- `desktop/` is an Electron adapter library, not another application launcher. It owns the native work required before a Host exists and after it stops. Profile and bundle composition owns ordinary Host and Client contributions; supported Node applications still launch through `dsh` profiles.
- Preserve authentication before workspace activation. Select account storage only from authenticated enterprise and stable employee IDs; prepare and verify the complete model configuration and credentials before starting the Host. Missing authentication, invalid configuration, partial writes, or uncertain outcomes must not start a default or previous account Host. Do not move these checks into an optional plugin that runs after workspace startup.
- Preserve revocation and shutdown guarantees. Unauthorized responses and hard expiry stop the Host and tasks and clear enterprise credentials. Account switching awaits the old Host's exit and clears renderer and browser state before another account starts. Shutdown failure prevents switching; old output must not reach the new account. Temporary synchronization failure permits cached access only until hard expiry, with visible feedback.
- Keep enterprise branding, signing inputs, application identity, and update destinations in enterprise release configuration. Reuse shared packaging and update machinery; enterprise release artifacts must not enter the official DSH publication sequence.
- Follow the [package instructions](../packages/AGENTS.md) for enterprise plugin code. Every enterprise package declaring `dsh.client` also follows the [Client instructions](../packages/client/AGENTS.md), including slot and props discipline, locale-owned UI copy, reactive state ownership, effect-owned registrations, and real-composition tests. Directory placement does not exempt enterprise UI from these rules. An extraction must preserve authentication, lifecycle, data isolation, and model behavior; a directory move alone does not establish compatibility. Update bilingual owner documentation and run the smallest checks covering the change.
